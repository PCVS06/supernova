# Agent feature catalogue research for Pi+

Research date: 2026-09-11  
Status: documented in live official documentation; not personally tested in this research pass.  
Scope: granular features relevant to customizable context/prompts, execution loops, subagents, tools, sessions, tracing, and graph/workflow orchestration.

The source set is intentionally first-party: OpenAI Codex and Agents SDK documentation, Gemini CLI documentation, and Google ADK documentation. Behaviors below are paraphrased; they are not claims that Pi+ already implements them.

## Standout findings for Pi+

### 1. Context is a layered runtime, not a string

Codex and Gemini CLI both make instruction discovery hierarchical and inspectable. The Agents SDK and ADK go further by separating instructions from runtime context, session state, memory, artifacts, and compaction/caching. Pi+ should therefore expose an “effective context” view with sources, scope, precedence, token contribution, and load timing.

### 2. There are two useful orchestration modes

The Agents SDK’s managed loop is the ergonomic default: the runtime owns turns, tools, guardrails, handoffs, and sessions. ADK’s graph model is the reliability-oriented complement: the developer explicitly owns nodes, edges, routing, and deterministic code. Pi+ should support both a conversational loop and an optional graph/workflow layer, with the same event and trace model underneath.

### 3. Delegation should be visible and bounded

Codex, the Agents SDK, Gemini CLI, and ADK all document delegation, but they differ in ownership: contained agent-as-tool calls, conversational handoffs, isolated subagent contexts, and graph nodes. Pi+ should show parent/child run relationships, specialist prompt, tools granted, model, turn/time limits, workspace, result contract, and whether control returns to the parent.

### 4. Tool management is a product surface

MCP appears across Codex, Gemini CLI, and ADK, while the Agents SDK adds hosted tools, deferred tool search, namespaces, and programmatic tool calling. The catalogue points toward a capability center with provider health, per-tool policy, approval mode, auth state, schema, deferred/loading state, and session-only enablement.

### 5. Reliability comes from policy and event evidence

Codex rules, Gemini hooks, Agents SDK guardrails/approvals, and ADK callbacks all create deliberate interception points. JSON-RPC/JSONL interfaces, sessions, checkpoints, and tracing make runs resumable and diagnosable. Pi+ should make every intervention a typed event with a reason, actor, policy source, and resume path.

### Suggested Pi+ priority order

1. Effective context inspector: layered files, prompt blocks, runtime context, token budget, and provenance.
2. Durable run/session model: resume, checkpoints, typed events, approvals, cancellation, and reconnection.
3. Capability center: tools, MCP servers, per-tool permissions, namespaces, and session-only toggles.
4. Subagent runtime: bounded specialists with isolated context/tools and visible parent-child traces.
5. Workflow graph view: sequential/parallel/loop/routing nodes with deterministic code steps.
6. Policy and observability: hooks/guardrails/rules plus trace and replay views.
