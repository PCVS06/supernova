# Feature catalogue for a customizable Pi+ coding harness

_Research date: 2026-09-11. Scope: Aider, Cline, Roo Code, Goose, OpenHands, SWE-agent, and Continue._

This is a source-backed feature catalogue, not a completeness claim or a recommendation ranking. It is grounded in the cited first-party documentation and repositories, with research assistance used for source discovery. No claim here should be read as a personally executed cross-agent workflow test. Each row is a concrete behavior that a Pi+ harness could study. `Documented` means the first-party source describes the behavior; `Experimental` means the source labels it experimental; `Proposed (Pi+)` is a clearly marked synthesis, not an existing feature of the named project.

The projects are not equivalent products. Aider, Cline, Roo Code, Goose, OpenHands, and SWE-agent are end-user agent/harness products or runtimes. Continue is primarily a configurable agent platform spanning IDE extensions, CLI, and CI. OpenHands and SWE-agent also expose framework/runtime surfaces. “Full harness” and “framework/library” below describe the relevant surface for that row, not the entire project.

## Reading the comparison

- **Distinctive context:** Aider’s graph-ranked repository map, Continue’s typed context providers, Roo’s layered rule directories, and OpenHands’ triggered skills are different ways to make context selective and reusable.
- **Loops and planning:** Cline separates Plan and Act; Aider separates architect and editor models; Goose emphasizes maintained plans and turn/context controls; OpenHands documents goal-judge continuation; SWE-agent exposes a configurable action/submit loop.
- **Human control:** Cline’s approvals/checkpoints, Goose’s permission modes, Roo’s mode/tool restrictions, Aider’s Git undo path, and SWE-agent’s inspectable trajectories place control at different points in the loop.
- **Sandbox and execution:** OpenHands and SWE-agent make runtime isolation a first-class deployment concern. Aider, Cline, Roo, Goose, and Continue expose more direct local/editor or shell integration, so a Pi+ harness should not assume their safety boundaries are interchangeable.
- **Framework versus harness:** Continue’s configuration model and OpenHands’ SDK catalogue are especially reusable as building blocks; SWE-agent’s runtime/configuration surfaces are unusually benchmark- and patch-oriented; the IDE/terminal products expose more opinionated user workflows.
